# 可观测管线

让每个数字都能回答来源、口径、采集时间和失败状态。页面读不到数据不等于上游失败，旧数据也不等于当天新观测。

## 1. 先定义数据契约

阅读 [快照契约参考](references/snapshot-contract.md)，为每类数据指定唯一所有者、来源、schema、时间字段、保留策略和载荷预算。

- 同一指标只在一个来源维护，其他板块引用 id，不复制第二份数字。
- 当前快照、历史趋势、明细清单和运行健康按读取需求拆分。
- 明确定义滚动窗口、累计值、相邻净变和固定 N 日净变，禁止混称。
- 首次采集只建基线，不伪造历史或把全量写成新增。

## 2. 设计采集与降级

1. 为请求设置超时、大小上限、分页上限、重试预算和响应 schema 校验。
2. 将网络失败、限流、格式变化、空集合和真正数值 0 分开处理。
3. 失败时保留上一次成功快照并标 `stale`；无历史时标 `unavailable`。
4. 部分来源成功时标 `partial`，不把未采集项静默删除。
5. 不使用过期响应覆盖更新快照；关键结构非法时拒绝部分写入。
6. 面向公开页面的错误使用固定安全文案，不泄露令牌、私有路径或响应原文。

## 3. 记录运行自身

在提交前写入运行记录，至少包含运行 id、attempt、作业状态、步骤 outcome、失败与缺失步骤、覆盖范围和保留策略。

- 读取步骤 `outcome`，不把被 `continue-on-error` 包裹后的作业 `conclusion` 当步骤事实。
- 缺少步骤映射时写 `unknown`，不默认全成功，也不推断所有步骤都失败。
- 运行记录只覆盖已经发生的采集与索引，不提前声称后续构建和部署成功。

## 4. 构建前端与导出

- 缺失或未知字段优雅降级，不生成假链接、假趋势或空的成功卡片。
- 对第三方文本转义，对 URL 使用协议与域名白名单。
- CSV 导出防止公式注入；日历只导出能确定时刻的节点，不猜时间。
- 历史样本过少时不解释斜率；缺失基线显示未知，不插值成 0。
- 大明细按需加载，但聚合 KPI 与明细加载状态不得形成两个冲突口径。

## 5. 分级验证与发布差异审查

顺序固定为：离线测试 → 网络采集 → 运行记录 → 提交快照 → 构建 → 部署。

1. **目标检查**：验证脚本语法、schema、分页、时间归一、负变化、缺失基线、保留窗口和安全边界。
2. **邻近回归**：检查页面实际引用的文件与 DOM id、相关采集器、失败降级、快照防回退和工作流权限；测试必须先于采集与提交。
3. **真实流程**：在暂存目录执行实际采集和构建，对比前后快照；部署后核对线上 JSON、页面板块、筛选、导出和采集健康，不能只凭工作流绿色宣布站点更新。
4. **差异审查**：检查工作流、采集器、前端和数据的最终差异，撤回无关权限扩张、依赖、格式化与产物修改；确认没有凭据、私有路径和意外历史改写。

任何检查实际未运行时报告“未运行”或“跳过”，不得写成通过。发布说明分别列出采集、构建、部署和线上核对的证据与覆盖范围。
