# YOLO 实验工作流

把模型结构、训练配置、评测、导出和部署分成独立回归层，再用同一条端到端流程串起来。不要用最终 mAP 一个数字替代所有验收。

## 1. 建立实验矩阵

开跑前阅读 [YOLO 实验清单](references/experiment-checklist.md)，冻结：

- 代码与模型配置版本、预训练权重和数据划分。
- 输入尺寸、batch、学习率、增强、精度、种子与硬件。
- 基线和候选之间唯一要研究的变量。
- 训练预算、checkpoint 保留、早停或止损条件。
- 训练、验证、导出和部署各自的验收入口。

## 2. 先跑最小回归

1. 解析模型配置，确认实际模块、参数和输出形状与预期一致。
2. 用小 batch 做前向与反向，检查 NaN、Inf、异常梯度和显存。
3. 跑短训练与验证，确认损失、标签、图像尺寸和指标路径连通。
4. 对 MoE 或动态路由额外检查专家负载、路由边界、空路由与合并前后语义。
5. 最小回归失败时先修当前层，不直接启动长训练。

## 3. 运行同口径对照

- 保持数据、增强、预算、输入尺寸和评测脚本一致。
- 记录参数、FLOPs、显存、吞吐和延迟的测量条件；理论量与实测量分开。
- 主指标之外保留分类、定位、召回和小目标等诊断信息。
- 单次小幅波动不直接写成提升；必要时用多种子或重复测量估计噪声。
- 保存配置、日志、权重、环境信息与结果索引，使结果能回查。

## 4. 验证导出与部署

按“源模型 → 导出图 → 推理运行时 → 目标后端”逐层对齐：

- 使用固定输入和同一预处理，比较输出形状、置信度与检测框。
- 区分导出失败、图优化变化、精度下降和后处理不一致。
- 动态 shape、NMS、量化与设备支持分别验证，不把未知支持写成兼容。
- 部署结果必须回到原始端到端输入复核，不能只验证中间算子。

## 5. 分级验证与实验差异审查

1. **目标检查**：模型解析、固定输入前向、反向和关键路由或数值断言通过。
2. **邻近回归**：短训练、验证、导出和相关模型配置回归通过，确认共享模块没有意外变化。
3. **真实流程**：回到原训练、导出或部署命令，在目标输入与后端核对最终权重、图和检测结果。
4. **差异审查**：对照实验矩阵检查代码、模型 YAML、数据、训练配置和导出设置，确保除研究变量与必要修复外没有未说明变化；清理本轮临时产物，不误删既有结果。

结果表至少包含配置 id、代码版本、数据版本、预算、指标、效率和证据路径。先报告已验证项，再列失败、跳过和未运行项。有效改动同步到项目 Runbook，结果写入 Records，不用会话记忆代替实验台账。
