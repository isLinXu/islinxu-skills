# 文档组织参考

## 选择规则

优先维护已有文档；只有独立阅读与维护价值明确时才新增。编号表达所属阶段，类型表达主要职责。

| 类型 | 文件名标记 | 维护内容 | 不承接的内容 |
| --- | --- | --- | --- |
| Criterion | `criterion` | 判断对象、质量标准、证据要求、适用边界 | 批次结果、临时操作 |
| Runbook | `runbook` | 现行 SOP、配方、验证、恢复、停止条件 | 单次实验推导 |
| Records | `records` | 输入来源、配置版本、产物、结果、验收与证据入口 | 通用规则的重复副本 |
| Probe | `probe` | 限定问题、样本、方法、结论和验证边界 | 自动升级为全量标准 |
| Special | `special` | 独立问题的研究、设计、诊断或治理依据 | 无关主线进展 |
| Todo | `todo` | 有限待办与完成条件 | 永久重复维护的规则 |
| Index | `index` | 导航与入口说明 | 需要单一归属的操作或指标 |

## 命名

```text
<编号>_<类型>_<主题>.md
```

标题使用 `# <编号> [类型] <主题>`。阶段主入口为 `x.y` 时，统一台账优先命名为 `x.y.0_records_<主题>.md`，使其紧邻主入口。

## 承接规则

- 操作与配方归 Runbook，质量判断归 Criterion，批次与实验结果归 Records。
- Probe 和 Special 保存推导、证据和边界，其他文档引用而非复制其规则。
- 一篇文档可以保留必要依据、结果和待办，但主要用途必须明确。
- 事实、决策和假设分开书写；类型与完成状态也分开。
- Probe、Todo 或 Special 结束后，先同步已采用内容到长期入口，再合并、保留或归档。
- 归档保留当时的验证边界，不把未验证事项改写为已完成。
- 文件迁移同步更新 Markdown 链接、纯文本路径和实际依赖，并保留迁移记录。
