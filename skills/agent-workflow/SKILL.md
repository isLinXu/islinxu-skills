# 长程 Agent 协作

把会话目标转化为可验证的工作流。简单修改直接完成，不机械套用完整流程。

## 1. 建立执行契约

在开始长程执行前写清：

- 目标与可验收产物。
- 任务边界、成本预算和停止条件。
- 当前工作区、验证入口和不能触碰的内容。
- 已观察事实、已确定决策、待验证假设。

方向性分歧先对齐；已确认范围内的实现判断自主推进。

## 2. 用文档承接状态

优先更新项目已有 Runbook 或 Todo。只记录下一步所需的状态，不预先穷举所有情况。需要新文档时，按 [文档组织参考](references/document-types.md) 选择类型与名称。

进度汇报只保留：已达成的验收项、最大卡点、下一步、明显成本风险。

## 3. 按方案执行并主动研究

1. 将工作拆成可验证的小步，每步保留输入、改动和验证结果。
2. 失败时先读错误与现场证据，定位原因，再选择能区分假设的实验。
3. 不重复相同失败调用，不通过隐藏错误、删除断言或放宽标准制造通过。
4. 优先复用项目已有的重试、续接、超时、产物验证与清理机制。
5. 记录恢复收益、额外耗时和明显 token 成本，再决定是否继续优化。

## 4. 必要时拆专项

只有真正阻碍主线的问题才拆专项。专项至少记录：

- 原始失败现象与复现入口。
- 已观察证据和已尝试措施。
- 待验证原因与有限实验安排。
- 什么结果允许返回主线。

最小实验只用于降低诊断成本，不替代真实场景验收。

## 5. 分级验证并审查差异

得到候选方案后按风险执行：

1. **目标检查**：运行能直接证明当前步骤的最小测试、静态校验或产物断言。
2. **邻近回归**：运行共享调用方、相邻模块和项目约定的回归门。
3. **真实流程**：回到原失败调用、端到端管线或实际交付路径复核，不能用专项小实验替代。
4. **差异审查**：逐项核对代码、配置、文档和生成物，撤回与主线无关的修改；只清理本轮产生的无用内容。

随后：

- 区分通过、失败、跳过和未运行，不把缺少检查写成没有风险。
- 清理本轮启动且不再需要的临时进程与文件，不影响其他任务。
- 将有效操作同步到 Runbook，将质量标准同步到 Criterion，将结果同步到 Records。
- 注明仍未知的根因、临时绕路和剩余风险，再结束或继续主线。

## 完成标准

只有产物存在、约定验证已执行且结果如实记录时才报告完成。无法完成时，交付当前证据、最大卡点和下一个最有区分度的动作。
