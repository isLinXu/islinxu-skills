# 论文精读

按四个阶段推进，使每阶段产物可直接被下一阶段使用。区分论文原文、官方代码、他人转述和自己的推测。

## 1. 问题定位

- 写出作者解决的问题、任务设定、输入输出和适用边界。
- 选择最接近的 1–3 篇工作，指出新意对应的具体机制或证据，而非“效果更好”等形容词。
- 将核心贡献改写成一个可证伪假设。
- 记录论文版本、发表时间和代码提交版本；版本不明时明确标注。

## 2. 方法拆解

- 画出数据流：输入 → 关键模块 → 输出，逐个标注已知张量形状。
- 对每个新增模块回答：解决什么瓶颈、为什么必须存在、去掉后哪个指标或行为应变化。
- 建立超参数表，区分原文明确值、代码默认值和复现待选值。
- 对齐公式、模块名称与官方代码路径；没有官方代码时不伪造对应关系。

## 3. 实验核对

- 核对数据集划分、预处理、指标定义、基线预算和统计窗口是否同口径。
- 对照每个贡献点检查消融；缺少对应消融时写“证据不足”，不替作者补结论。
- 检查数据泄漏、不公平对比、选择性报告和仅单次运行的不稳定差异。
- 将论文自报结果与自己实测结果分栏保存，绝不相加或混写。

## 4. 复现清单

输出可直接开工的清单：

1. 数据来源、版本、划分与预处理脚本。
2. 模型改动的最小差异和对应代码入口。
3. 训练配置：步数、学习率、batch、精度、种子、增强和硬件。
4. 评测脚本、指标定义与预期区间；预期区间无依据时标为待测。
5. 显存、耗时和 checkpoint 策略；估算值明确标为估算。
6. 首先运行的最小冒烟实验，以及它能排除的失败类型。
7. 回到完整论文配置的验收路径和停止条件。

## 5. 分级验证与复现差异审查

按实际任务选择层级，不把阅读笔记包装成已经复现：

1. **内容核对**：关键论断回到原文、公式、表格或官方代码，检查版本和上下文。
2. **方法检查**：用形状推导、最小张量或模块级冒烟验证对数据流的理解。
3. **实验验证**：先跑最小训练与评测，再回到论文完整配置或明确等价的真实流程；记录实际覆盖范围。
4. **差异审查**：对照论文、官方代码和本地改动，逐项说明模型、数据、配置和环境的必要差异；移除与复现目标无关的修改。

论文自报、官方代码默认、本地推测和实测结果始终分栏。只完成内容核对时报告“已精读”，完成真实实验后才报告相应复现结果。

## 完成标准

任何未在论文、代码或实际运行中出现的数字都标为“推测”或“待测”。引用必须能回到实际读过的原文、代码或数据；无法访问全文时，明确本次精读覆盖范围。
