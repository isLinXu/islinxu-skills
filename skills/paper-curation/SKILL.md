# 论文清单维护

把“读到一份文件”和“清单发生真实变化”分开处理。先建立稳定身份与基线，再报告新增、移出和更新。

## 1. 定义来源与口径

为每个来源记录仓库或 URL、文件路径、解析形态、归属、覆盖范围和抓取时间。表格、机器 JSON、主题归档和一次性报告分别选择解析器，不强塞进同一规则。

明确：

- 什么行算条目，什么行只是导航、榜单或统计。
- 全量、抽样、下限或滚动窗口中的哪一种口径。
- 本站实测与来源自报分栏保存，不相加、不互为分母。
- 抓取失败、未尝试、空清单和格式变化的不同状态。

## 2. 建立稳定条目身份

优先使用规范化 arXiv id；没有 arXiv id 时使用标题身份。不要以“文件名 + 分区”作为论文身份，否则移动分区会被误报为增删。

使用随附脚本获得可复现身份：

```bash
python scripts/paper_identity.py --arxiv "https://arxiv.org/abs/2401.00001v2"
python scripts/paper_identity.py --title "多模态评测：方法与挑战"
```

脚本只对身份字符串做确定性归一，不验证论文是否真实存在；元数据仍需回到一手来源核对。

## 3. 核验元数据

- 标题、作者、年份、会议和链接优先回到论文原文、arXiv 或出版方页面。
- 保留版本与访问日期；技术清单中的时效性结论必须能追溯。
- 不根据标题猜测代码、项目页或作者身份。
- 无法确认的字段留空并标注原因，不用合理想象补齐。

## 4. 维护增删台账

1. 首次抓取只建立基线，不把全部条目写成“今日新增”。
2. 同一来源内重复出现或跨分区移动不算增删。
3. 滚动窗口的移出标为窗口机制，不写成数据丢失。
4. 抓取失败时保留上次台账，不删除未观察到的 id。
5. id 台账被截断时，将后续增删标为不可比或下限，不报告虚增数量。
6. 更新节奏按目标文件的提交历史判断，不用整个仓库的 `pushed_at` 代替。

## 5. 分级验证与发布差异审查

1. **目标检查**：测试身份归一、重复条目、无链接行、中文标题和滚动窗口等关键 fixture。
2. **邻近回归**：运行同形态解析器、相邻来源和台账差异测试，确认解析修改没有改变无关来源口径。
3. **真实流程**：重新读取实际来源，与上一份快照和台账比较；抓取失败时保留旧结果，不制造增删。
4. **差异审查**：检查最终 Markdown、JSON 和导出内容，只允许预期条目、元数据和必要格式变化，避免无关重排或全文件改写。

发布前确认：

- 条目身份可重复生成，重复运行不产生重复条目。
- 新增与移出能回到相邻快照和台账。
- 实测、自报、样本和全量的口径标注完整。
- 正文不复制外部数值指标；指标留在自己的快照来源中。
- 对导出文本做链接白名单、HTML 转义和电子表格公式注入防护。
