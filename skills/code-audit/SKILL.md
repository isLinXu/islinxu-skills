# 实验代码审计

先建立对调用链和数据流的正确认知，再修改代码。不要把症状当病因，也不要为现代化而重写正确设计。

## 流程

1. **限定范围**：读取项目约定，从入口、配置和相关子目录定位代码，避免无边界扫描产物与环境目录。
2. **静态阅读**：按调用链自顶向下读，记录输入、状态、关键分支、输出和已有验证入口。
3. **建立问题清单**：每条问题附文件、行号、触发条件、后果和证据；无法定位的直觉不列为缺陷。
4. **排序**：错误结果 > 崩溃或数据损坏 > 资源浪费 > 可维护性 > 风格。
5. **构造反例**：为空输入、单元素、重复、超长、非法值和边界数值设计最小复现。
6. **先写回归**：让测试在旧实现上因目标原因失败，再做最小修复。
7. **逐项验证**：一次只修最高优先级的一项，立即回到原失败场景并运行相关回归。
8. **检查同类模式**：限定范围搜索相同错误，报告实际结论，不无限扩大重写。

## 数值与实验附加检查

读取 [数值与实验检查清单](references/numerical-checklist.md)，重点核对随机性、精度、归一化、张量形状、数据泄漏和评测口径。

## 分级验证与差异审查

1. **目标检查**：确认新回归在旧实现上因目标原因失败，并在修复后通过。
2. **邻近回归**：运行共享函数、调用方和相邻数值路径，检查是否引入新偏差。
3. **真实流程**：回到原失败命令、训练或评测管线，核对最终产物而不只看辅助函数。
4. **差异审查**：逐块检查修改，确保只包含当前缺陷、必要兼容和对应测试；撤回无关格式化、重构和既有死代码删除。

每项修复单独记录验证层级。目标检查通过但真实流程未运行时，状态保持“未完整验收”。

随后单列：

- **验证结果**：列出实际运行的命令及通过、失败或跳过状态。
- **建议不动的地方**：说明哪些设计正确，不应为了风格推翻。
- **未验证假设**：没有证据支持的内容单独保留，不混入缺陷表。

## 纪律

- 每个结论都由代码位置、验证工具或最小复现支撑。
- 先修复最高严重度问题，不批量混入无关重构。
- 小测试成功后回到真实管线验证。
- 临时绕路必须标注，不直接固化为生产配置。
