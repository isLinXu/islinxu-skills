# 多模态评测

先冻结评测契约，再运行模型。总分只是汇总视图，不能替代切片、失败分析和可复核证据。

## 1. 冻结评测契约

阅读 [评测契约参考](references/evaluation-contract.md)，明确模型版本、数据版本、提示词、解码参数、图像预处理、工具权限、指标和统计窗口。

确保基线与候选共享数据、预算、评测脚本和口径。任何一项不同都单独标注，不直接宣称提升。

## 2. 检查数据与答案路径

- 检查训练、微调和示例上下文中的测试集泄漏。
- 保存样本 id、输入引用、原始输出、解析后答案、标签与错误原因。
- 将解析失败、拒答、超时、空输出和真正答错分开统计。
- 对多项选择、自由回答、数值、计数和空间关系分别定义等价答案规则。
- 人工抽查解析器，尤其检查“正确但格式异常”和“错误却被规则救回”的样本。

## 3. 设计指标与切片

- 报告样本数和分母，比例指标同时给出计数。
- 按能力、模态、难度、来源和关键风险切片；小切片只作诊断，不夸大显著性。
- 保留总体、宏观平均与微观平均的定义，不混用。
- 对 Judge 评分报告模型、Prompt、温度、随机种子和人工校准样本。
- 对 Agent 任务区分完成率、轨迹效率、工具错误和一致性，不用单一总分掩盖失败类型。

## 4. 比较两次运行

将同口径结果保存为 JSON 后，使用：

```bash
python scripts/compare_metrics.py baseline.json candidate.json --output diff.json
```

脚本只计算显式数值差异，不判断统计显著性，也不把缺失切片当成 0。输入格式与解释规则见 [评测契约参考](references/evaluation-contract.md)。

## 5. 形成结论

报告顺序固定为：

1. **结论**：只写数据支持的变化。
2. **口径**：模型、数据、配置、脚本版本和运行时间。
3. **总体与切片**：列出计数、分母、差异和缺失项。
4. **失败分析**：给出可回查的样本 id 与失败类别。
5. **不确定项**：单次波动、Judge 偏差、小样本和未覆盖场景。
6. **下一步**：选择能区分假设的最小实验，而非无条件扩大跑量。

## 6. 分级验证与实验差异审查

1. **目标检查**：用已知答案测试解析器、等价答案、缺失值和失败分类，确认分母正确。
2. **邻近回归**：复查相关能力切片、指标汇总和 Judge 校准集，避免局部规则改变无关样本。
3. **真实流程**：使用冻结契约完成实际模型调用，保存原始输出并重新计算指标；不能只用缓存或手工样例宣布结果。
4. **差异审查**：对照基线与候选的数据、模型、提示、解码、工具、脚本和报告，列出所有变化；出现研究变量之外的差异时先解释，不直接宣称提升。

没有原始输出、样本 id、配置和评测脚本版本的结果不进入正式对比。复跑结果不同先检查口径与解析路径，不挑选更好看的一次作为正式结果；失败、跳过和未运行切片单独列出。
